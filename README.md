# План закупок

Локальный сайт для подготовки заказов поставщикам по выгрузкам IEK и Systeme Electric.
Он показывает прогноз, рекомендуемое количество, причину расчёта и риск дефицита.
Менеджер может поправить количество и скачать CSV. Заказы поставщикам не отправляются.
Раздел «BI-аналитика» показывает историю продаж и сравнивает сохранённые прогнозы
с фактическими продажами после окончания прогнозируемого периода.

## Запуск на своём компьютере

Нужны Python 3.11–3.13, интернет при первом запуске для установки зависимостей и
предоставленные ZIP-архивы. ZIP не требуется распаковывать. Файлы с исходными
выгрузками не включены в репозиторий.

**Windows:** дважды нажмите `run.bat` (установленный Python должен поддерживать
команду `py -3`). **macOS/Linux:** в терминале запустите `sh run.sh`.
Первый запуск создаст окружение и установит зависимости. Последующие запускаются
из уже готового окружения. Для ручной установки выполните команды ниже.

Если старое окружение `.venv` было создано без `pip`, новая версия `run.bat`
попробует восстановить его автоматически через `ensurepip` без интернета.
Если эта команда отсутствует в установленном Python, установите полную версию
Python с `pip`, удалите папку `.venv` и запустите `run.bat` заново.

```bash
python -m venv .venv
```

Активируйте окружение: Windows PowerShell — `.venv\Scripts\Activate.ps1`, macOS/Linux —
`source .venv/bin/activate`. Затем:

```bash
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Откройте адрес, показанный в терминале (обычно `http://localhost:8501`).
Загрузите один или оба ZIP в левой панели, проверьте параметры и нажмите «Рассчитать заказ».
Исходные файлы, параметры и расчёты сохраняются на компьютере и доступны после
перезапуска. Для остановки нажмите Ctrl+C в терминале.

## Оформление и работа с заказом

Интерфейс использует фирменное оформление ekt.kz: оригинальный логотип,
цвета и шрифт PT Sans. Все ресурсы хранятся локально; источники и лицензия
шрифта перечислены в `assets/SOURCES.md`. Экран адаптирован для телефона.

После расчёта можно искать товары по названию, артикулу или коду 1С,
выбирать поставщика и менять количество к заказу. Результат и ручные количества
сохраняются в базе. CSV содержит строки текущего фильтра. Если изменить исходные
файлы или параметры, нужно снова нажать «Рассчитать заказ»: появится отдельный
расчёт без ручных правок. Предыдущий прогноз и его правки остаются в «BI-аналитика» →
«История», откуда расчёт можно снова открыть. Ручное количество заказа не меняет
исходный прогноз спроса.

## BI-аналитика и контроль точности

- **Обзор продаж:** помесячная динамика в штуках, фильтры поставщика, категории
  и периода, выгрузка CSV. Используется последний сохранённый архив каждого
  поставщика; повторные загрузки не суммируются.
- **Точность прогноза:** сравнение одного сохранённого расчёта с фактом по товарам,
  графики отклонений, MAE, WAPE, процентное смещение и выгрузка сравнения.
- **Загрузить факт:** импорт полного отчёта продаж поставщика за указанный период.
- **История:** расчёты, версия модели, параметры, связанные исходные файлы
  и загрузки фактических продаж.

Для загрузки факта подготовьте CSV UTF-8 с колонками `supplier`, `code`, `date`, `qty`:

```csv
supplier;code;date;qty
IEK;001234;2026-09-01;12
IEK;001234;2026-09-02;4
```

Один файл относится к одному поставщику (`IEK` или `Systeme Electric`). Даты —
`ГГГГ-ММ-ДД`, количество — неотрицательные валовые продажи в штуках без вычета
возвратов. Коды сохраняются как текст, включая ведущие нули. Повторные строки
одного товара за день суммируются внутри файла.

Укажите даты отчёта **включительно** и подтвердите его полноту по **всем товарам
поставщика**. Отсутствующие товары и дни в этом периоде означают нулевые продажи.
CSV только с заголовками подтверждает нулевые продажи за весь период. Без
загруженного полного отчёта отсутствие строк не считается нулём.

Новая загрузка заменяет продажи поставщика во всём указанном интервале, включая
обнуление отсутствующих в новом файле товаров. Повторная загрузка не удваивает
продажи; при пересечении периодов заменяется только пересечение, остальные дни
сохраняются. База хранит исходные файлы, нормализованные отчёты и историю импортов
для проверки происхождения данных.

Метрики рассчитываются только для завершённого горизонта, каждый день которого
покрыт полными отчётами. При неполных данных строки ожидают факта и не входят в
метрики. Оценивается **сохранённый прогноз спроса**, а не количество заказа:

- **MAE, шт.** — средняя абсолютная ошибка по оценённым товарам.
- **WAPE, %** — сумма абсолютных ошибок / сумма факта × 100.
- **Смещение, %** — сумма (прогноз − факт) / сумма факта × 100; плюс означает
  завышение прогноза.

При нулевой сумме факта WAPE и процентное смещение не определены; MAE остаётся
доступной. Процентная ошибка отдельного товара с нулевым фактом тоже не определена.
Расчёты с началом в день сохранения или раньше помечаются как исторические
сценарии и показываются отдельно по переключателю. Продажи при отсутствии товара
могут быть ниже спроса: эти метрики сравнивают прогноз с продажами.

## Хранение и резервная копия

SQLite-база `data/procurement.sqlite3` хранит оригиналы загруженных файлов,
нормализованные наборы данных, выбранные источники и параметры, неизменяемые
прогнозы, отдельные ручные количества заказа и фактические продажи. Повторные
одинаковые источники и наборы данных не создают лишних копий. Папка `data/`
исключена из Git: публикация кода не переносит рабочие данные.

Путь можно задать переменной окружения `PROCUREMENT_DB_PATH` перед запуском.
Это одно локальное рабочее пространство: все сеансы приложения с одной базой
видят общую историю и настройки. Для переноса или резервного копирования
остановите приложение и скопируйте файл базы либо всю папку `data/`. Для
восстановления поместите копию по тому же пути при остановленном приложении.

## Данные и ограничения

Сайт читает помесячные продажи, историю операций, кратность заказа, остатки и товары
в пути. Связь между файлами устанавливается по коду 1С. Последний неполный месяц
не используется для определения обычного месячного спроса. Прогноз строится на
взвешенной истории последних шести завершённых месяцев с сезонным коэффициентом.
Сезонность рассчитывается по двум последним полным годам доступной истории,
без привязки к конкретным календарным годам; при редкой истории артикула
используется сезонность поставщика. Устойчивый рост оценивается по двум соседним
трёхмесячным периодам, а дополнительный прирост задаётся вручную.

Начало прогноза выбирается явно и должно быть позже последнего дня операций
в выбранных архивах. Горизонт равен сроку поставки плюс интервал между расчётами;
он может различаться по поставщикам. В сохранённых строках интервал представлен
как `[Начало прогноза, Конец прогноза)`: конечная дата не включается. В таблице
сравнения BI показывается последний включённый день. История после даты начала
не используется, а неполный месяц старого архива не становится полным только
из-за выбора более поздней даты прогноза.

Редкие крупные продажи в одном документе ограничиваются по медиане размера операции
для артикула. Их превышение исключается из регулярного месячного спроса. Если таких
продаж много, они считаются повторяющимися. В выгрузке нет ID клиента, поэтому
определить именно крупный заказ одного клиента пока невозможно.

Если загружен журнал stockout, отсутствовавший спрос оценивается по соседним месяцам.
Без журнала корректировка не применяется. Для IEK остаток из архива относится к
началу сентября 2026 года. Для Systeme Electric берётся «Свободный остаток» из
сводной таблицы без подтверждённой даты. Поэтому **до рабочего заказа** загрузите
актуальные остатки. Сроки новой поставки (по умолчанию 30 дней) — демонстрационные
параметры. Товар в пути без даты прибытия отображается, но не вычитается.

Дополнительные файлы CSV кодируются UTF-8 и имеют заголовок:

```csv
supplier,code,balance
IEK,010500003_,48
```

```csv
supplier,code,start,end
IEK,010500003_,2026-08-01,2026-08-07
```

Значение `supplier` — точно `IEK` или `Systeme Electric`. Количество к заказу
округляется до указанной кратности; при отсутствии кратности используется 1 и
выводится предупреждение. При отсутствии остатка позиция не получает заказ.
Оценка упущенного спроса, поиск выбросов и коэффициенты роста — подсказки для
менеджера; итог требует проверки перед утверждением.

## Проверка расчёта

```bash
python -m unittest discover -s tests -v
```

Тесты проверяют расчёт заказа, границы прогноза, сезонность, точность на полных
периодах, сохранение после открытия новой сессии, повторные и пересекающиеся
импорты, неизменяемость прогнозов и откат при ошибке записи. Тест реальных архивов
запускается, если архивы доступны локально по пути `../upload/`.
